# scenario-manager 规范

## Purpose

场景包管理与执行入口（Web）。列表与执行端点由 scenario-engine（#15）提供真实实现：`GET /v1/scenarios` 返回真实场景包列表，`POST /v1/scenarios/run` 同步执行场景并返回结构化报告；页面以报告数据渲染执行结果。

## Requirements

### Requirement: 场景管理预览页

场景管理页必须（MUST）调用 `GET /v1/scenarios` 展示真实的场景包列表（名称、描述），每项提供"执行"按钮。执行按钮必须（MUST）调用 `POST /v1/scenarios/run`，并以报告数据渲染执行结果（总结果与每步状态）；执行期间必须（MUST）展示进行中状态，禁止重复提交。当引擎返回失败报告时，页面必须（MUST）以可读形式展示失败步骤与错误信息，而不是静默失败。本需求取代 Change 14 的 mock 列表与 501 占位行为。

#### Scenario: 场景列表展示

- **WHEN** 用户打开场景管理页
- **THEN** 页面展示引擎返回的场景包（含内置示例），每项含名称与描述

#### Scenario: 执行未实现的场景

- **WHEN** 用户点击某场景的执行按钮并等待完成
- **THEN** 页面展示该次运行的总结果与每步状态；失败步骤的错误信息可见

#### Scenario: 执行期间禁止重复提交

- **WHEN** 某场景正在执行时用户再次点击其执行按钮
- **THEN** 前端不发出第二次请求（按钮处于禁用/进行中状态）
