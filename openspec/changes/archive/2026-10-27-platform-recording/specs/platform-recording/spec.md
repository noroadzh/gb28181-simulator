# Spec Delta

## Purpose

平台侧录像：把平台拉取的实时流按时间分段写入磁盘，形成可按 (节点, 通道, 时间窗) 查询的录像库，并作为 HTTP-FLV 与 SIP 回放的数据源。

## ADDED Requirements

### Requirement: 拉流自动录制

平台节点的实时拉流会话建立后，系统 MUST 自动把该会话的 PS 帧写入录像分段文件。录制 MUST 在以下任一情形封段并结束：会话结束（stop / 对端 BYE / 空闲回收）、节点停止、单段达到配置的分段时长。分区文件 MUST 记录所属节点、通道与起止时间，并 MUST 能在进程重启后通过扫描录制目录重建索引。

录制失败（磁盘错误、权限不足）MUST NOT 中断拉流：系统 MUST 记录 warn 日志并继续转发媒体。录制默认开启；关闭时不得创建任何文件。

#### Scenario: 拉流即开始录制

- **WHEN** 平台对一个通道成功建立实时会话
- **THEN** 该会话的 PS 帧被写入一个分段文件
- **AND** 该分段出现在录像库中，起止时间覆盖实际录制区间

#### Scenario: 会话结束封段

- **WHEN** 实时会话因 stop、BYE 或空闲回收结束
- **THEN** 当前分段被关闭，录像库中的结束时间被更新

#### Scenario: 按分段时长切分

- **WHEN** 录制持续超过配置的分段时长
- **THEN** 当前分段结束，新的分段开始，二者时间不重叠

#### Scenario: 重启后仍可查询

- **WHEN** 进程重启后查询某个已有录像的通道
- **THEN** 启动扫描得到的录像与该通道的历史分段一致

#### Scenario: 录制失败不影响拉流

- **WHEN** 写入分段失败（如目录不可写）
- **THEN** 拉流与 FLV 输出继续，系统记录 warn 日志

### Requirement: 录像库查询

系统 MUST 支持按 (节点, 通道, 时间窗) 查询录像，窗口为空表示不限。结果 MUST 返回每条录像的标识、起止时间、大小与文件位置，并按开始时间升序。时间窗与录像区间有交集即视为命中。

#### Scenario: 按窗口查询

- **WHEN** 查询某通道 [T1, T2] 的录像
- **THEN** 只返回与 [T1, T2] 有交集的分段，按开始时间升序

#### Scenario: 无录像的通道

- **WHEN** 查询的通道没有任何分段
- **THEN** 返回空列表，而不是错误

### Requirement: 录像回放数据源

系统 MUST 能按录像标识与时间窗重放分段内容，产出连续的 PS 帧流。回放 MUST 在窗口结束或数据耗尽时自然结束，并 MUST 支持被调用方提前取消（关闭 HTTP 连接或 SIP 对话结束时停止读取与发送）。同一录像 MUST 支持多个并发回放。

#### Scenario: 重放一个分段

- **WHEN** 对某条录像发起回放
- **THEN** 消费方按写入顺序收到该分段的 PS 帧

#### Scenario: 取消回放

- **WHEN** 回放过程中调用方取消
- **THEN** 读取停止，文件句柄释放，不再产出帧

#### Scenario: 并发回放

- **WHEN** 同一录像同时被两个消费者回放
- **THEN** 两者各自收到完整内容，互不影响
