# GB28181 模拟器操作手册

> 面向运维 / 联调人员。基于**单实例合壳**部署（一套 Web、同进程 platform + device）。  
> 当前测试机：`10.96.1.125`，路径 `/slow2/gb28181-simulator`，版本以页面右上角 / `GET /v1/version` 为准。  
> 页面级字段说明见 [Web 管理界面操作手册](web-ui-guide.md)；装机细节见 [Docker Compose 部署](deploy-docker-compose.md)。

## 1. 快速入口

| 用途 | 地址 |
|------|------|
| Web UI（唯一） | http://10.96.1.125:18080 |
| 健康检查 | http://10.96.1.125:18080/healthz → `{"status":"ok"}` |
| 平台 SIP（对外对接） | `10.96.1.125:15060` UDP/TCP |
| 设备 SIP（同进程内注册） | `10.96.1.125:15061` UDP/TCP |

- 打开 Web 先进入**登录页**（`http.auth.enabled`）。测试默认：`admin` / `Gb28181@Web`（与 SIP 设备账号无关）。
- 顶栏切换：**全部 / 平台 / 设备**（合壳角色视角，不是两套系统）；右上角可退出。
- 帮助页：侧栏「帮助」，含对接四步与端口说明。
- 未登录时 `/v1/*` 返回 401；`/healthz` 仍公开（容器健康检查）。

| device | `34020000001310000001` | 模拟设备，向本机 platform 注册 |

## 2. Web 登录

配置项（`config.yaml`）：

```yaml
http:
  auth:
    enabled: true
    username: admin
    password: "Gb28181@Web"
    session_ttl_hours: 24
```

| 说明 | |
|------|--|
| 作用范围 | Web UI + `/v1` API（Cookie / Bearer / `access_token` 查询参数） |
| 不保护 | `/healthz`、`/v1/health`、登录相关接口、静态资源 |
| 与 SIP 关系 | **无关**；SIP 设备账号仍在「账号管理」 |
| 关闭方式 | `enabled: false` 后重启进程 |

改密：改配置 → 重启 `./deploy.sh --skip-build`（或重建镜像）。会话存内存，重启后需重新登录。

## 3. 角色视角怎么用

| 顶栏 | 节点列表 | 侧栏额外菜单 | 典型工作 |
|------|----------|--------------|----------|
| 全部 | platform + device | 全部菜单 | 日常总览 |
| 平台 | 仅 `platform-*` | 账号管理、级联中继 | 开账号、看级联会话、平台拉流 |
| 设备 | 仅 `device` | 媒体源 | 加通道、配片源、PTZ/对讲 |

侧栏颜色会随视角变化（深蓝 / 墨绿），便于辨认当前角色。

## 4. 标准联调流程（第三方 ↔ 模拟平台）

```
第三方 VMS / IPC
      │  SIP REGISTER / CATALOG / INVITE
      ▼
模拟器 platform（:15060）
      │  同进程注册 / 拉流
      ▼
模拟器 device（通道 + 媒体源）
```

1. **开账号**：顶栏「平台」→「账号管理」→ 选 platform 节点 → 新增 20 位国标编码 + 密码。  
2. **准备通道**：顶栏「设备」→「节点概览」→ 进 device →「通道」→ 新增通道；通道卡片配媒体源（合成图 / RTSP / 上传 MP4 / HLS）。  
3. **第三方注册**：对端向 `10.96.1.125:15060` 发 REGISTER（Digest；账号与上一步一致）。  
4. **目录 / 点播**：对端 MESSAGE Catalog、INVITE 点播；也可在本机 Web 上用平台通道「开始拉流」自测。  
5. **浏览器预览**：通道详情 HTTP-FLV「开始播放」（设备看本地源；平台先拉流再播下级）。

## 5. 平台侧日常操作

### 5.1 账号管理

路径：顶栏「平台」→「账号管理」。

- 新增 / 删除注册账号，改密码。  
- 仅对 `platform-large` / `platform-small` 节点有效。  
- 账号落 SQLite，重启保留；与 YAML 首次 seed 无关（DB 已有节点后以页面为准）。

### 5.2 平台拉流与录像库

路径：平台节点 → 通道列表 → 通道详情。

1. 选传输 **UDP** 或 **TCP**（附录 D）。  
2. 「开始拉流」→ 成功后「开始播放」预览。  
3. 「停止拉流」结束会话。  
4. 「平台录像库」：拉流落盘分段的查询与 FLV 回放。

> 平台通道本身无本地媒体源 / PTZ / 对讲；那些在**设备**通道页操作。

### 5.3 级联中继观测

路径：顶栏「平台」→「级联中继」。

- 只读查看媒体 B2BUA 中继会话（传输、端口等）。  
- 拆链仍走 SIP BYE，UI 不强制拆。

### 5.4 文件下载（HTTP API）

平台主动按时间窗下载录像写入库：

```http
POST /v1/nodes/{platformId}/channels/{channelId}/download
Content-Type: application/json

{"start":"2026-11-05T02:00:00Z","end":"2026-11-05T02:05:00Z","transport":"udp"}
```

`transport` 可为 `udp`（默认）或 `tcp`；成功返回 `call_id` 与 `transport`。写入键为 `download:{channelId}`。

## 6. 设备侧日常操作

### 6.1 通道

路径：顶栏「设备」→ 节点卡片「通道」或进通道列表。

- **新增**：20 位通道编码 + 名称；即时进 Catalog。  
- **删除**：确认后从 DB 移除。  
- **媒体源**：合成图（无外源测试）/ RTSP / 本地文件（可拖拽上传）/ HLS。

### 6.2 实时预览、PTZ、对讲、抓图

通道详情页：

| 能力 | 说明 |
|------|------|
| 播放 | HTTP-FLV，播设备本地媒体源 |
| PTZ | 方向 / 变倍等（部分子命令可能 501） |
| 对讲 | 浏览器麦克风 ↔ 设备 PCMU |
| 抓图 | 下载当前帧 JPEG |
| 录像 | 设备侧录像列表 / 回放 |

### 6.3 节点级媒体源

路径：侧栏「媒体源」（设备视角）。  
配置节点默认片源；通道级配置优先。

## 7. 节点生命周期

路径：「节点概览」。

| 操作 | 含义 |
|------|------|
| 启动 | 拉起信令栈；device 会向上级 REGISTER |
| 停止 | 停服务，状态回到 idle/离线 |
| 注销 | 发 Expires=0 注销（有 registration 时） |
| 新建 / 编辑 / 删除 | 运行期改拓扑（落库）；勿与 YAML 混用覆盖预期 |

默认部署 `auto_start: true`：进程起来后节点应自动为 **online**。若为 idle，在卡片上点「启动」。

## 8. 运维启停（测试机）

```bash
ssh root@10.96.1.125
cd /slow2/gb28181-simulator

./deploy.sh              # 构建镜像（若有新二进制）并启动 gbsim
./deploy.sh --skip-build # 仅重启，不重建镜像
./deploy.sh --fresh-data # 清空 ./data 后启动（丢库，慎用）
./down.sh                # 停止

docker compose ps
docker compose logs -f gbsim
curl -s http://127.0.0.1:18080/healthz
curl -s http://127.0.0.1:18080/v1/nodes
```

| 路径 | 说明 |
|------|------|
| `config.yaml` | 单实例配置（首次空库灌节点） |
| `data/` | SQLite、录像等；UID 10001 |
| `binary/gb28181-simulator-linux-amd64` | 预编译二进制 |
| `platform/`、`device/` | 旧双容器遗留目录，默认不再使用 |

> 节点真源是 **DB**。改 `config.yaml` 的 `nodes:` 不会覆盖已有库；要干净拓扑用 `--fresh-data` 或 Web 改节点。

### 发版到测试机（开发侧）

1. 本地：`make web`，再交叉编译 `linux/amd64` 二进制。  
2. `rsync` 二进制到 `/slow2/gb28181-simulator/binary/`，同步 `config.yaml` / compose / `deploy.sh`（若有变更）。  
3. 服务器：`./deploy.sh`（或 `--skip-build` 仅换层时按脚本习惯重建镜像）。  
4. 核对 `GET /v1/version` 的 `commit` / `version`。

## 9. 常用排查

| 现象 | 处理 |
|------|------|
| 一直停在登录页 / 401 | 核对 `http.auth` 用户名密码；清 Cookie 后重登；确认配置已挂载并重启 |
| healthz 不通 | `docker compose ps` / `logs gbsim`；确认宿主 18080 映射 |
| 节点 idle | 卡片「启动」；看日志注册/端口占用 |
| 设备注册失败 | 账号密码是否与「账号管理」一致；platform 是否 online；同进程应为 `127.0.0.1:5060` |
| 平台拉流无画面 | 设备通道是否有媒体源；先「开始拉流」再播；试 TCP |
| Catalog 无通道 | 设备侧是否已建通道；等 catalog 轮询（约 30s）或触发查询 |
| 改 YAML 不生效 | DB 已有节点；用 Web 改或 `--fresh-data` |
| 权限 denied 写库 | `chown -R 10001:10001 data` |

辅助工具：

- **抓包面板**：看 REGISTER / INVITE 是否到达，可下 pcap。  
- **实时日志**：侧栏「实时日志」。  
- **故障注入**：联调对方异常路径（丢包、超时等）。
